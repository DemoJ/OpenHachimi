# 浏览器与网页操作指南

在访问任何 URL 前，先判断任务是否只是“打开/查看指定页面”。如果是简单、低风险、目标明确的浏览器任务，直接使用 `browser_navigate(url)`，不要先做资源发现或搜索。

对于需要提取稳定内容、总结资料或对比信息的网页任务，再根据域名和路径推断目标网站是否可能提供公开 API、RSS、JSON、XML 或文档页面等稳定资源。只要有合理可能，优先使用 discover_web_resources 或 web_fetch 获取内容。

但以下情况使用 browser 工具：
- 公共接口不足以完成任务
- 必须交互、登录或检查真实渲染页面
- 用户明确要求使用浏览器

## 操作流程
1. 使用 `browser_navigate(url)` 打开页面
2. 首次访问或页面跳转后，使用 `browser_get_state()` 获取可交互元素列表
3. 已确认多个目标元素 ID 时，在同一回合内连续发出所有交互指令；只有页面发生跳转或重大刷新、导致 ID 失效时，才重新调用 `browser_get_state()`

## 常用交互模式
- 搜索提交：`browser_type` 输入关键词后，直接 `browser_press_key('Enter', 输入框ID)` 提交，无需寻找搜索按钮
- 下拉选择：原生 `<select>` 用 `browser_select_option(元素ID, 选项文本)`；自定义组件（输出无 select 标记）用 browser_click 展开后点选项
- 悬停菜单：`browser_hover(元素ID)` 展开后重新 `browser_get_state`
- 页面在加载/懒加载中：`browser_wait_for(text='目标文本')` 等待内容出现后再继续
- 返回上一页：`browser_go_back()`
- 元素标记 `[iframe N]` 表示其位于页面内嵌框架中，click/type 等操作对其照常有效，无需特殊处理
- 视觉兜底：当 get_state 无法理解页面（canvas/图表/复杂视觉布局/验证码图片）时，用 `browser_screenshot(question='...')` 截图并获取画面描述

## 防呆与效率
- 调用 `browser_click` / `browser_type` 时建议带上 `description` 参数（元素的简短描述）。系统会校验描述与元素实际内容，页面已变化导致 ID 指向错误元素时会拒绝操作——这能防住绝大多数"点错元素"问题
- `browser_click` 的返回会附带页面变化摘要（跳转/新标签页/交互元素增减）。若摘要显示"无变化"且预期应有响应，可能是点错了目标或页面懒加载中，可 `browser_wait_for` 后再 `browser_get_state`
- 元素行内 `[当前:xxx]` 表示输入框当前值 / checkbox 勾选态 / select 选中项，无需额外查询
- `[+N 个相同元素已折叠]` 表示有 N 个同款元素被折叠显示，其 ID 仍可正常引用

## 浏览器探索原则
遵循全局的【深度探索与自主思考】原则，但只在用户要求分析、调查、总结或任务明显需要网页信息收集时启用。在简单打开/查看任务中，到达用户指定页面即可停止，不要额外滚动、搜索或发散探索。

## 登录与账号操作策略
- 优先利用已有登录态：直接 `browser_navigate` 到目标页面，用 `browser_get_state` / `browser_extract_content` 检查是否已登录，已登录则不要碰登录表单
- 需要首次登录时：导航到登录页后**停下来**，向用户输出"请在打开的浏览器窗口中手动完成登录，完成后回复「继续」"，等待用户指令。人工登录一次后浏览器会保存会话，后续任务自动带登录态
- 未经用户明确要求，不要代替用户填写密码、验证码、短信验证码；遇到 2FA/二次验证一律交还用户
- 登录类站点（X/Twitter、Google、Facebook、Amazon 等强风控站点）被拒绝登录/提示异常/临时限制时：不要重试、不要换 IP 建议，直接报告用户并等待指示。这类限制通常与账号或网络环境评分有关，重试只会加重

## 遇到人机验证时
立即停止所有工具调用，向用户输出："遇到人机验证（[具体原因]）。请在浏览器中手动完成验证后回复「继续」。"，不得尝试绕过或重试。
